# Classroom access

Date: 30 September 2026. Scope: sign-up for a whole room, a way back from a forgotten passphrase, and a sleeping public database. This is not a release-wide pass of the 20 checks.

The public class remains https://keelai-os.vercel.app. A Vercel preview link is not this class. The local class at http://127.0.0.1:3960 keeps its own SQLite roster.

## What changed

A shared network can create 120 accounts an hour. That allowance is stored with the class record, so it is the same on every server instance. Signing in from that network is allowed 120 times in fifteen minutes. Each email can try five times in five minutes. The five-try cap is what stops a passphrase from being guessed. It is counted on the email, so one room does not share a single bucket.

A signed-in person changes the passphrase from the account page. The current passphrase is required. Other sessions end. There is no reset email, because Keel has no mail sender. The super admin, frankleroyvan@gmail.com, can set a new passphrase from the class book. The person's work stays and the old sessions end. That form does not reset the super admin. A staff account cannot use it.

The public database is still the free Neon plan. It can sleep after a quiet stretch. A request that finds it waking waits and tries once more. The first visit can be slow, and a second try may be needed. A daily check opens `/api/health`. On the free Vercel plan a more frequent check is rejected at deploy, and a daily check does not keep the database awake. No paid database plan was started.

Those accounts were deleted. `SELECT count(*) FROM user WHERE email LIKE 'keel-access-%'` returned 0.
- A production dump was restored into a throwaway local Postgres 18, then destroyed. The restored counts were 12 week rows, 12 published, 0 users, and 0 profiles. The dump was 26608 bytes and `pg_restore` exited 0. The dump file and the env pull were overwritten and removed. Nothing was written back to the hosted database. The hosted roster was empty at the time of that dump.
- The first public sign-up after that deploy returned 500. PostgreSQL treats `SET count = count + 1` as ambiguous. The rate statement now says `keel_rate.count`. That statement was run once against the hosted database, and the trial row was deleted. SQLite still accepts it.
